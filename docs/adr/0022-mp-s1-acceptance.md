# ADR 0022 — MP-S1 (Declared Shop Capability Model) implementation, acceptance and gate evolution

- **Status:** Accepted
- **Date:** 2026-11-06
- **Deciders:**
  - Project owner: freeze of spec revision 3.1 and implementation authorisation, under a strict scope lock with
    five conditions.
  - Research Director: preliminary and final independent reviews of revisions 1–3. These are input, not
    ratification (Law 22).
  - Chief Systems Engineer: audit, specification, implementation and verification.
- **Constitution in force:** v1.1.0. Ownership per CAP-0001 (affirmed in ADR-0021 Q1).
- **Related:** `specs/milestones/MP-S1-declared-shop-capability-model.md` (revision 3.1, frozen),
  `docs/milestones/MP-S1-completion-report.md`, ADR-0021, ADR-0010 (the gate-evolution precedent),
  `docs/research/next-capability-gap-assessment.md` (addendum A1–A7)

## Context

- Every plan, verdict, reuse decision and schedule depended on a hard-coded capability model identified only by a
  hand-assigned SemVer label. A user could not declare their own shop.
- A read-only probe at `ee46767` reproduced the defect. Two models share the label `1.0.0`, and the second drops
  aluminium. RM2 reuse then returned the stored `MANUFACTURABLE` verdict with the guard on, while a fresh run gives
  `NOT_MANUFACTURABLE [MATERIAL_UNSUPPORTED]`.
- Owner condition 1 makes that bug the primary acceptance requirement.

## Decisions (as built)

1. **Data contract.** Contract suite `0.4.0 → 0.5.0`, additive only:
   - a new `ShopCapabilityModel` schema (1.0.0);
   - one optional `ProductionPlan.capability_model_ref` = {`shop_content_hash`, `shop_declaration_hash`,
     `evidence_class`}.

   Plans carrying the ref use plan `schema_version` 1.1.0. Code-model plans carry no ref and stay 1.0.0,
   byte-identical. Every other 0.4.0 file is byte-identical, and the bindings were regenerated by the existing tool.
2. **Loader.** `mini_prometheus/shop_declaration/shop_model.py`:
   - pure, no default and no fallback;
   - a closed `ShopModelIssueCode` with complete, sorted issue lists;
   - declared-intent rules: every op mapped or `unsupported_ops`; every mapped capability provided or
     `unsupported_capabilities`; every resource capability mapped;
   - cyclic precedence is refused;
   - strict JSON for files: duplicate keys and NaN/Infinity are refused.

   It builds the **existing** `ProcessCapabilityModel`, which gains an optional `source: ShopModelSource`.
3. **Two identities.**
   - `shop_content_hash` = the semantic capability basis.
   - `shop_declaration_hash` = that hash + `evidence_class` + `declaration` (declarer, date, sources).
   - `model_version` (the contracted label, already part of the frozen RM1 plan identity), `display_name` and
     `notes` are in neither hash.
   - Reuse and every binding check use the declaration hash.
4. **Binding guards G1–G5.**
   - G1: the planner writes the ref.
   - G2: `runner.run` requires plan ref = model ref before verification. A mismatch raises
     `ShopIdentityMismatchError` past the INFRA_ERROR handler and writes nothing. `job_set` applies the same check
     per job.
   - G3: the episode reader re-derives the hash of every ref-carrying plan and requires (ref ⇔ schema 1.1.0).
   - G4: the RM2 key is `(design hash, label, declaration hash | None)`.
   - G5: the schedule records `shop_model_ref` only for a declared shop, and the independent checker refuses any
     missing, different or mixed ref (`METADATA_MISMATCH`).
5. **Verdict traceability (spec §3.8).** `orchestration/verdict_trace.py` provides `VerdictTrace`, `trace_run` and
   `trace_job`, all fail-closed. The Noetica `Verdict` envelope is **not** modified. With
   `--capability-model-file`, the runner prints one trace line. Declared-shop scheduling refusals name the plan and
   the shop, and state that scheduling keeps no episode by design.
6. **Cross-shop precedent (spec §3.7).**
   - Guarantee 1: a new import-linter contract (the 6th) forbids every verdict path from importing `precedent`,
     `judgment`, `precedent_runner` or `judgment_runner`.
   - Guarantee 2: `orchestration/precedent_basis.py` annotates each precedent entry with one of five bases. Only
     `SAME_DECLARATION` may count as advisory evidence. Frozen RM3/RM4 code is untouched.
   - The pre-authorised scope reduction (deferring guarantee 2) was **not needed**.
7. **CLIs.** Both CLIs gain `--capability-model-file`, mutually exclusive with `--capability-model`. An invalid file
   exits 2 and lists every issue. Without the flag, output is unchanged.
8. **Runtime** `0.12.0 → 0.13.0`.

## Deviations from the frozen spec (recorded, not silent)

1. **Loader package.** Spec §3.2/§5.1 placed `shop_model.py` in `manufacturing_constraints/`. The frozen CI byte-diff
   covers that whole directory against `rm2-complete` ("a new file there is still caught"). Putting the file there
   would have needed a fourth gate evolution, which §9 does not allow. It lives in a new content package,
   `mini_prometheus/shop_declaration/`, and the gate evolution stays exactly as ratified.
2. **AC4 tolerance example values.** The spec's row (a 0.005 mm minimum vs a 0.01 mm request) is **feasible**,
   because the oracle refuses only a request strictly tighter than the minimum. That row could never produce
   `TOLERANCE_UNSUPPORTED`. The variant uses a `cap.mill` minimum of 0.2 mm against the bracket's 0.1 mm request.
   The criterion is unchanged; only the example values are corrected.
3. **`reuse_runner.py` change size.** Two lines rather than the spec's "one line". The pinned-content gate is as
   ratified, and the diff is shown above.
4. **`ShopModelSource`** also carries `declared_by`, `declared_on` and `display_name` for the §3.4 presentation
   line. They are in no identity: the declaration hash takes them from the document.
5. **Scheduling modules** import `CapabilityModelRef` through `mini_prometheus.shop_declaration.shop_model`, because
   the RM11 boundary test allows only stdlib and `mini_prometheus` imports there.
6. **Not updated:** `contracts/schemas/manufacturing/README.md`. It is a frozen 0.4.0 file under AC8, and editing it
   would trip the manifest check. The new schema documents itself (its `description`, and this ADR).

## Consequences

- A declared shop can never reuse a verdict made under a different shop content or evidence basis. The reproduced
  bug is closed, and a test pins it.
- Code-model behaviour is unchanged: all RM1–RM15 goldens and corpora pass, and the 902-row RM8 golden is reproduced
  row by row by the declared mirrors.
- The RM2 label-only identity for **code** models is pinned unchanged (T4.9). Declared shops are the supported path.
- Real-shop validation is still absent: MP-E1 stays blocked (ADR-0021 Q5).

## Alternatives rejected

These are listed in spec §5:
- the hash in the SemVer label;
- the hash in provenance only;
- the ref in `ProcessStep.params`;
- a code-only format;
- a single hash;
- hashing the code models;
- retrieval filtering in frozen RM3/RM4.
